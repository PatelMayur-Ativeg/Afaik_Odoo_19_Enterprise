Purchase Request Module

User Guide & Step-by-Step Examples

This document explains what the module does, how the approval flow works, and how to use it with practical examples.

Part 1: Module Functionality

1.1 Purpose

The Purchase Request module is the starting point for internal purchasing. Employees describe what they need; managers approve; then the company either buys from a supplier (Purchase Order) or moves stock internally (Internal Picking). Everything is tracked on one form with a reference number (e.g. PR00015).

1.2 Main features

  • Create purchase requests with automatic reference number (PR#####).
  • Two product categories: General and IT (filters available products).
  • Three ways to fulfill each line: buy, take from stock, or both (partial).
  • Request items not in the catalog (New Product Request).
  • Approval workflow with email to the department manager.
  • Budget check for managers (planned, actual, remaining).
  • Link to Purchase Orders and Stock Transfers from the request.
  • Discussion and history on each request (messages at the bottom).

1.3 Who uses the module

  • Employee (Requester) — Creates and submits requests.
  • Manager (Requisition Responsible) — Reviews, approves, or rejects.
  • PR Admin / PR IT Admin — Creates RFQ for new products; may edit cost price.
  • Procurement — Works on linked Purchase Orders in the Purchase app.
  • Warehouse — Validates internal transfers linked to the request.

1.4 Where to open it

  • App menu: Purchase Requests
  • Or: Purchase → Orders → Purchase Requests

1.5 Approval flow (status bar)

Draft→ Waiting for Review→ Waiting for Approval→ In Progress→ Done

Rejected stops the process. The requester is notified by email when submitted.

StatusMeaning
DraftYou are still editing.
Waiting for ReviewSubmitted; waiting for manager.
Waiting for ApprovalManager is reviewing.
In ProgressApproved; purchase or warehouse work started.
DoneRequest closed.
RejectNot approved.

1.6 Form sections

  • Header — Buttons: Submit, Approve, Reject, Done, Create RFQ (special cases).
  • Main fields — Employee, department, manager, category, dates, budget (if visible).
  • Products tab — Standard catalog lines.
  • New Products Request tab — When New Product Request is enabled.
  • Picking Details — Warehouse operation and locations.
  • Smart buttons — Purchase Orders count, Pickings count (warehouse managers).

1.7 Line options (Requisition Action)

ActionWhen to use
Internal PickingMove stock between locations (no supplier).
Purchase OrderBuy from vendor (supplier required on product).
PartialUse available stock first; buy the remaining quantity.

Available QTY on each line shows stock in locations marked for PR. Qty to Buy and Qty to Receive are calculated for partial lines.

1.8 Budget fields (when visible)

Visible to department managers and users with budget access. Shows whether the department has enough budget before approval. Remaining budget turns red if the request may exceed the limit.

Part 2: How to Use (By Role)

2.1 Employee — Create a request

  1. Open Purchase Requests and click New.
  2. Confirm Employee and Department (filled from your HR profile).
  3. Select Category: General or IT.
  4. Optional: PR Type, Budget Type, description, dates.
  5. Products tab: add lines (product, qty, action, vendors if buying).
  6. Check Picking Details if using internal stock.
  7. Click Submit for Approval.

You can only use Submit if you created the request.

2.2 Manager — Review and decide

  1. Open requests in Waiting for Review or Waiting for Approval.
  2. Review lines, budget, and picking details.
  3. Optional: click Request approval to move to Waiting for Approval.
  4. Click Approve to accept, or Reject to decline.
  5. When work is finished, click Done.
  6. Use Reset to Draft to send back for correction if needed.

2.3 Procurement — New products and purchase orders

  1. For catalog items: after approval, process via Purchase Orders linked to the PR.
  2. Click the Purchase Orders smart button on the request.
  3. For new products: open PR with only New Product lines, status Waiting for Review.
  4. Click Create RFQ, select vendor, confirm.
  5. Complete RFQ/PO in Purchase app as usual.

2.4 Warehouse — Internal transfers

  1. Open related pickings via the Pickings button (stock managers).
  2. Validate the transfer when goods are moved.
Part 3: Step-by-Step Examples

Example 1 — Purchase IT equipment (buy from supplier)

Situation: IT staff needs 3 laptops. They are not in local stock; must be purchased.

Steps

  1. Login as employee. Menu: Purchase Requests → Purchase Requests → New.
  2. Category = IT Category. Requisition date = today.
  3. Products tab: Add a line.
  4. Requisition Action = Purchase Order.
  5. Product = Laptop (must be under an IT product category).
  6. Quantity = 3. Select Vendor(s) on the line.
  7. Click Submit for Approval. Status = Waiting for Review.
  8. Manager receives email. Manager opens PR, reviews, clicks Approve.
  9. Procurement opens PR → Purchase Orders button → confirms PO with supplier.
  10. When delivered, manager sets request to Done.

Example 2 — Office supplies from stock (internal transfer)

Situation: Admin needs 50 notebooks available in the main warehouse.

Steps

  1. New Purchase Request. Category = General Category.
  2. Products tab: Product = Notebook, Quantity = 50.
  3. Requisition Action = Internal Picking.
  4. Check Available QTY shows enough stock.
  5. Picking Details: verify operation type and locations (from department).
  6. Submit for Approval.
  7. Manager approves.
  8. Warehouse: open Pickings from the request and validate transfer.
  9. Manager marks PR as Done.

Example 3 — Partial: part from stock, part to buy

Situation: Need 20 chairs. Only 8 in stock; buy 12 from supplier.

Steps

  1. New PR. Category = General Category.
  2. Add line: Product = Office Chair, Quantity = 20.
  3. Requisition Action = Partial.
  4. System shows Available QTY = 8, Qty to Receive = 8, Qty to Buy = 12.
  5. Select vendor for the purchase portion.
  6. Submit and get manager approval.
  7. After processing: internal move for 8 chairs + purchase order for 12.
  8. Track both from Purchase Orders and Pickings buttons on the PR.

Example 4 — New product not in catalog

Situation: Request a new software subscription not listed as a product.

Steps

  1. New PR. Enable checkbox: New Product Request.
  2. Products tab is hidden; use New Products Request tab instead.
  3. Enter Description = Annual CRM subscription.
  4. Cost price = estimated amount. Request qty = 1.
  5. Submit for Approval.
  6. PR Admin or PR IT Admin: open PR in Waiting for Review.
  7. Click Create RFQ. Choose vendor. Click Create RFQ in the popup.
  8. A Purchase Order is created with a text line (no product required).
  9. Continue negotiation and confirmation in Purchase module.

Example 5 — Manager checks budget before approval

Situation: Department has a yearly budget; manager must verify before approving.

Steps

  1. Employee submits PR with lines and estimated costs.
  2. Manager opens PR. Budget section is visible (manager or budget access).
  3. Read: Planned Amt, Actual Amt, PR Amount, Remaining Budget.
  4. If Remaining Budget is red, discuss with employee or finance.
  5. Approve only if acceptable; otherwise Reject or ask for changes via messages.
Quick Reference — Common Issues
  • No products in list — Wrong Category (General vs IT) on the request.
  • Cannot submit empty request — Add at least one line (unless New Product Request).
  • Error on Purchase Order line — Product needs a supplier in its settings.
  • Cannot see other people's requests — Normal for standard users.
  • Create RFQ not visible — Only for new-product requests in Waiting for Review.
