1. What this application does

This application lets employees ask the company to buy items or move stock internally. Instead of creating a purchase order directly, staff fill in a Purchase Request (PR). The request then moves through review and multi-level approval before purchase orders or internal transfers are created automatically.

In simple terms:

  • You request — describe what you need, quantities, and category (General or IT).
  • Your manager reviews — sends the request into the formal approval chain.
  • Configured approvers approve — one or more levels (by user or security group).
  • Procurement runs — the system can create RFQs, purchase orders, and/or stock pickings.
  • Request is closed — marked Done when the process is complete.
Tip: You will receive email and in-app notifications when a request needs your action or when it is approved or rejected.
2. Who does what (user roles)

Purchase Request User

Creates and submits own purchase requests. Cannot approve others’ requests.

Purchase Request Manager

Line manager / requisition responsible. Sees requests assigned to them. Can send for approval, reset to draft (with rights).

Approval level users / groups

Defined in Approval Configuration. See Approve and Reject when it is their turn.

PR IT Admin / PR Admin

Can create RFQs at configured stages, fill requisition actions on lines, and use extra procurement buttons.

Purchase manager (setup)

Maintains Approval Configuration and purchase settings.

5. Steps for the employee (requester)
Step 1 — Open a new request
Go to Purchase Requests → Create.
Step 2 — Fill header information
  • Employee — usually yourself (filled automatically).
  • Requisition Responsible — your line manager (often filled from employee record).
  • Category — General Category or IT Category (required; drives approval rules).
  • Requisition date, deadline, and description as needed.
  • New Product Request — tick only if the product does not exist in the catalogue yet.
Step 3 — Add lines
  • Existing products: use the Products tab — choose product, quantity, unit of measure, remarks.
  • New products: use the New Products Request tab — description, estimated cost, quantity.
Step 4 — Picking details (if needed)
On Picking Details, set picking type and source/destination locations for internal moves.
Step 5 — Submit
Click Submit for Approval. Status becomes Waiting for Review. Your manager receives an email notification.
Before submitting: Add at least one product line (or new product line). Empty requests cannot be submitted.

After submit, you can follow progress on the same form and from email notifications. You do not need to click Approve unless you are also an approver.

6. Steps for the line manager (requisition responsible)

When a request is Waiting for Review and you are the requisition responsible (or primary approver per configuration):

Step 1 — Open the request
From Purchase Requests list or from the email link.
Step 2 — Review content
Check products, quantities, category, budget (if shown), and picking details.
Step 3 — Request approval
Click Request approval. Status becomes Waiting for Approval. The first approval level receives email and in-app notification.

If no approval configuration exists for that category, the system may confirm the request immediately and create purchase documents (same as final approval).

Optional — Reset to Draft
Managers with rights can use Reset to Draft to send the request back for correction (when visible).
7. Steps for approval levels (dynamic approval)

When status is Waiting for Approval and you are in the current approval user list or group:

Step 1 — Open the request
You should see buttons Approve and Reject.
Step 2 — Admin level only: set requisition action
If you are an IT/General admin at an admin approval level, extra columns appear on product lines:
  • Requisition Action — required before approving.
  • Qty to Buy / Qty to Receive — for partial scenarios.
  • Vendor — for purchase or partial lines.
Use the refresh icon next to Analytic Account to copy the header analytic account to all lines if needed.
Step 3 — Approve
Click Approve.
  • If more levels exist, the next approvers are notified and status stays Waiting for Approval.
  • On the last level, the request moves to In Progress, purchase orders and/or pickings are created, and the requester is notified.
  • If all lines are Internal Picking only, a picking may be created and status set to In Progress at that level.
Step 4 — Or reject
Click Reject, enter a reason in the popup, and confirm. Status becomes Rejected; the requester is notified.

Track who approved at each level on the Approval Info tab (level, users/groups, date, approved by).

8. Steps for IT / General admin (PR Admin)

Create RFQ — during approval (catalogue products)

When status is Waiting for Approval, your approval level has Create RFQ Access, and RFQ is not yet created: click Create RFQ to generate draft/confirmed purchase orders per vendor from lines marked Purchase Order.

Create RFQ — after approval (extra)

When status is In Progress, Create RFQ (highlighted) may appear to create an additional RFQ from purchase-order lines.

New product — wizard RFQ (base module)

For New Product Request in Waiting for Review or Waiting for Approval, IT/General admin may see Create RFQ (wizard) to enter vendor quotations for new items before catalogue products exist.

Approve — new product requests

For new-product requests, Approve may require that at least one RFQ/PO exists (purchase_count > 0) before the final approve button works — create RFQs first, then approve.

10. Product lines & requisition actions

For standard (catalogue) products, admins set Requisition Action on each line before final approval:

ActionWhat happens when request is confirmed
Internal Picking Creates an internal stock transfer (move from source to destination location).
Purchase Order Creates a purchase order / RFQ for the selected vendor(s) with the requested quantity.
Partial Can create both a picking (receive quantity) and a purchase order (buy quantity) per vendor rules.

Other useful line fields: Available QTY (stock on hand), Vendor (tags), Analytic Account (cost centre).

11. Budget information (when visible)

Budget fields appear for users with budget access (typically managers and admins):

  • Budget — linked analytic budget for the department/account.
  • Planned / Actual / PR Amount / Remaining Budget — help check if the request fits the budget.
  • Remaining Budget turns red if the request would exceed budget.
A warning may appear when line amounts change if budget is exceeded. Coordinate with finance before forcing approval.

13. Administrator setup (approval configuration)

For purchase managers setting up the system:

Step 1 — Enable category-based approval
Settings → Purchase → set Approval based on to Request Category.
Step 2 — Create approval configuration
Purchase Requests → Configuration → Approval Configuration → Create.
  • Name — e.g. “IT Purchase Approval”.
  • Category — General or IT (must match PR category).
  • Companies — limit to relevant companies.
  • Primary approval — Line Manager (manager sends to chain) or Own Approval (employee can request approval).
  • Buyer — user assigned on generated purchase orders.
Step 3 — Define approval lines
On tab Approval Details, add one row per level:
  • Level — unique number (1, 2, 3…).
  • Approve Process By — specific Users or Group.
  • Label type — Verified / Supported / Reviewed / Approved By (for reports).
  • Is Admin Level? — tick if IT/General admin must set requisition actions on lines.
  • Create RFQ Access — tick on the level where admins may create RFQ during approval.
Step 4 — Assign user groups in Odoo
Ensure employees have: Purchase Request User (requesters), Manager (managers), PR IT Admin / PR Admin (admins), and membership in approval groups defined above.
14. Common questions

I submitted but I see no buttons — is it broken?

After submit, status is Waiting for Review. Only your requisition responsible sees Request approval. Wait for them or ask them to act.

I am an approver but I do not see Approve

  • Confirm status is Waiting for Approval.
  • Confirm you are in the user list or group for the current level (see Approval Info tab → Next Approval).
  • For new-product requests, create RFQs first if required.

What is the difference between Approve and Confirm?

Approve (dynamic approval) moves the request through approval levels. Confirm (base module, when no dynamic config) creates POs/pickings from approved lines. Final approval usually calls confirm automatically.

Where are purchase orders created?

Open the PR and click the Purchase Orders smart button. They are also under Purchase → Orders.

Can I delete a request?

Only in Draft. After submit, use rejection or reset to draft (if you have rights).

How do I search my requests?

Use list filters: My Requests, Assigned to Me, or filter by status (Draft, Waiting for Review, etc.).
